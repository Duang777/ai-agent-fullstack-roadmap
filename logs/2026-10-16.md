## 今日学习
- 知识点：2.3 A2A（Agent-to-Agent）协议（按 A2A 1.0）
  - 分层：模型 API 管模型与工具调用格式，MCP 管 Agent 与工具，A2A 管 Agent 与 Agent；远程 Agent 是不透明的自主系统
  - Agent Card：`/.well-known/agent-card.json`；supportedInterfaces 有序、第一项首选；capabilities 没声明的能力必须报错；skills 是描述不是 schema
  - 任务：终态 COMPLETED / FAILED / CANCELED / REJECTED，中断态 INPUT_REQUIRED / AUTH_REQUIRED
  - taskId 只由服务端生成，带了必须存在；contextId 与 taskId 不一致必须拒绝；只给 taskId 时推断 contextId
  - 结果：默认阻塞到终态或中断态；returnImmediately + GetTask；SendStreamingMessage 第一个事件是任务快照；推送 webhook
  - 版本：每个请求带 `A2A-Version`，没有按 0.3；JSON-RPC 错误码 -32001 到 -32009

## 问题与思考
- 执行任务如果用 HTTP 请求的 context，returnImmediately 返回后任务立刻被取消
- CancelTask 先 cancel 再写 CANCELED 有竞态：Executor 抢先返回会被记成 FAILED；改成先写状态再 cancel
- 订阅时检查状态、生成快照、登记订阅要在同一把锁里，否则会漏事件
- 把远程 Agent 做成工具：input-required 不是错误；工具描述要写明“对方看不到你的对话历史”
