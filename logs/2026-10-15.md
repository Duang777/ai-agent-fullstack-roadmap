## 今日学习
- 知识点：2.1 Function Calling / Tool Use 机制与并行调用（模块 02 开始）
  - 五步流程：模型不执行工具，只输出调用；工具定义注入系统提示，占上下文、算 token
  - 两家格式：OpenAI `function_call`（`arguments` 是 JSON 字符串，用 `call_id` 对应）→ `function_call_output`；Anthropic `tool_use`（`input` 是对象）→ 下一条 user 消息里的 `tool_result`（`is_error`）
  - strict：OpenAI 要 `additionalProperties: false`、全部 required、可选用 null；Anthropic `strict: true`；仍要自己校验
  - tool_choice：auto / required(any) / 指定 / none / allowed_tools；Opus 5.5、Sonnet 5.5、Fable 5.1、Mythos 5.1 不支持强制调用；强制调用跳过思考；改 tool_choice 打掉消息缓存
  - 并行：`parallel_tool_calls: false` / `disable_parallel_tool_use`；结果同一条消息、结果在前；拆开会教坏模型
  - 执行：只读并发（上限、去重），副作用串行失败即停；错误变成有指导性的结果
  - 流式：按 output_index / content block index 拼接，done 后再执行
- 课件：[notes/02-tools/01-function-calling.md](../notes/02-tools/01-function-calling.md)

- 知识点：2.2 MCP（按 2026-07-28 规范）
  - Host / Client / Server；模型不知道 MCP，Host 在 MCP 工具定义和模型 API 工具定义之间转换
  - Tools 模型控制、Resources 应用控制、Prompts 用户控制；Roots / Sampling / Logging 已弃用
  - 无状态：去掉 initialize 握手和会话，每请求 `_meta` 带 protocolVersion 和 clientCapabilities，结果带 resultType；必须实现 server/discover；跨调用状态用显式句柄
  - 协议错误（JSON-RPC error）vs 工具执行错误（isError）；资源不存在 -32602
  - 多轮请求：input_required → 新 id 重发 + inputResponses + 原样 requestState；requestState 要 HMAC 并绑定参数和过期时间
  - stdio：stdout 只写协议消息；Streamable HTTP：单端点 POST、镜像头与 body 一致（-32020）、校验 Origin
- 课件：[notes/02-tools/02-mcp.md](../notes/02-tools/02-mcp.md)

## 问题与思考
- 4 个 50ms 只读调用：并发 51ms，`MaxParallel=1` 时约 200ms
- 键顺序不同的相同参数（`{"city":"北京","unit":null}` 与 `{"unit":null,"city":"北京"}`）只执行一次，两个 call_id 都有结果
- 执行器先跑只读再跑副作用，会打乱“先写后读”；练习 2 改成按相对顺序分段

- MCP：requestState 只签“已确认”不绑定参数，攻击者能用 a/b 的确认删除 victim/prod
- MCP：协议层无状态，但内存里的购物篮是应用层状态，多实例部署要放共享存储
