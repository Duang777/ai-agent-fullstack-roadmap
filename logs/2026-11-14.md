## 今日学习
- 知识点：4.3 Claude Agent SDK：agent 循环、六步权限、hooks、子 agent 与会话
  - Claude Code 当库用：`query()` 启动一个 `claude` 子进程，一个会话一个进程，会话记录在本地磁盘
  - 循环：每个内容块一条 `AssistantMessage`；`max_turns` 要算上最后的纯文本回答；预算在响应之后比较，会超出一次响应
  - 工具：只读工具并发、有副作用的顺序执行；自定义工具是进程内 MCP server（`mcp__server__tool`）
  - 六步权限：hooks → deny 规则 → ask 规则 → 权限模式 → allow 规则 → `canUseTool`；被自动批准的调用到不了回调；`allowed_tools` 约束不了 bypass
  - hooks：并行执行，`deny` > `defer` > `ask` > `allow`；失败默认放行，`onFailure: "block"` 才 fail closed；`defer` 挂起一个调用，resume 会话后再决定
  - 子 agent：只拿到 prompt 字符串，只交回最终消息；深度 / 并发 / 预算三个上限；父会话在 plan 时子 agent 继承 plan，子 agent 的 bypass 永远不生效
  - 会话：continue / resume / fork；跨主机用 SessionStore；文件靠 checkpoint，对话靠会话

## 问题与思考
- 三个框架的审批：LangGraph 在节点里暂停、恢复时重跑节点；OpenAI 在工具执行前结束 run、交出 RunState；Claude 默认在循环里阻塞等回调，要跨进程就用 hook 返回 defer。后两者都不重新生成那次工具调用，但都不保证外部动作只执行一次
- 权限规则是字符串匹配：`Bash(rm *)` 拦不住 `/bin/rm`。规则是策略，沙箱和容器才是边界
